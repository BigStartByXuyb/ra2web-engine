# 架构

## 分层

| 包                 | 职责                                                            | 允许依赖         | 明确不做                     |
| ------------------ | --------------------------------------------------------------- | ---------------- | ---------------------------- |
| `packages/formats` | 读取原版数据格式：MIX / INI / CSF / SHP / VXL / HVA / TMP / MAP | 无               | 不认识"单位""武器"等游戏概念 |
| `packages/rules`   | 把 INI 转成强类型领域模型（单位、武器、建筑、国家、模式）       | formats          | 不做模拟、不碰渲染           |
| `packages/sim`     | 确定性模拟：tick、指令、移动、战斗、经济、生产                  | rules            | 不碰 DOM/WebGL/网络          |
| `packages/render`  | 把状态画出来（体素、精灵、地形、界面）                          | sim(只读)、rules | 不修改模拟状态               |
| `packages/net`     | 锁步联机：指令广播、校验、重放                                  | sim              | 不实现渲染                   |
| `packages/app`     | 前端组装：加载资源、开房间、菜单、输入                          | 全部             | 不含游戏规则                 |

## 数据流

```
用户文件(游戏安装/MOD)
        │  formats: 解 MIX、读 INI/CSF/SHP/VXL
        ▼
原始字节 → rules: 领域模型(强类型)
        │
        ▼
sim: 按 tick 推进的确定性状态  ──►  render: 每帧读取状态绘制
        │                                   ▲
        ▼                                   │
net: 指令同步 / 重放  ──────────────────────┘
```

## 为什么这样切

- **模拟与渲染彻底分离**：模拟不许碰浏览器 API，才能做到"同一份模拟跑在 Node 里做回归测试"，
  也才能让联机重放和本地对局走同一条代码路径（这是原版锁步模型的前提）。
- **格式层零业务概念**：MOD 会塞进各种奇怪文件，格式层必须能"不认识也照读"，避免被业务假设绑死。
- **反向依赖禁止**：`render` 一旦能写 `sim`，确定性和联机校验就废了。

## 素材来源可替换

绘制层只依赖"一帧画布 + 贴地锚点"这一个接口（`UnitArt.frames[].canvas/anchorX/anchorY`、
建筑的 `StructureSprite`），所以素材从哪来是可换的：

| 来源               | 位置                               | 状态                               |
| ------------------ | ---------------------------------- | ---------------------------------- |
| 原版 VXL/SHP 现算  | `packages/render`                  | 默认：读体素与调色板实时渲染       |
| 超清贴图（A 路）   | 覆盖包里的 `<单位>.png` 8 朝向贴条 | 已做：按文件名优先命中，不动原文件 |
| 真 3D 材质（B 路） | 同一条接缝（glTF + PBR，实时渲染） | 目标路线                           |

规则：新增素材来源时**只换帧的生产者**，不动模拟；锚点必须由新来源自己给出（锚点错了，
选中判定、阴影与倒影会一起错位）。三种来源**逐单位混用、按可用性降级**：

```
3D 模型（glTF + PBR）  →  8 朝向超清贴条（PNG 覆盖包）  →  原版 VXL/SHP 现算
```

降级只看"这个单位的资源在不在"，所以同一局里可以一部分单位走 3D、一部分走贴图、其余走原版。
三条路的投影与贴地锚点必须一致（`screenX=(x−y)`、`screenY=((x+y)/2−z)`，贴地枢轴在精灵底边
中点／模型原点），否则切换来源时单位会跳位。

## 与逆向产物的关系

逆向得到的伪代码**不进源码树**。它存放在 `docs/engine/` 下作为参考证据，被 `sim` 的实现引用：
每条行为规则在注释里标注对应的原版函数地址与证据文件，便于日后核对。

## 项目组织与构建（多项目 / composite）

每个包是一个**独立的 TypeScript 项目**，由根 `tsconfig.json` 的 `references` 串联；`tsc -b`
按依赖顺序构建，产出 `dist/*.js` + `dist/*.d.ts`。包与包之间通过**包名**引用（解析到 `dist` 的类型声明），
不是通过相对路径引用源码。

这样做的收益：依赖方向由构建图强制（`sim` 想 import `app` 会直接构建失败），每个包可独立构建与发布。

### 硬性规则

1. **源码只在 `src/`，产物只在 `dist/`**（`rootDir: src`、`outDir: dist`、`composite: true`）。
2. **测试与工具不放进 composite 项目**。它们由根 `tsconfig.tests.json` 承载（`noEmit`，可用 `paths`
   直接引用源码），否则 `rootDir` 会报 `TS6059`。
3. **不要用 `paths` 把包名映射到源码**：那会让 composite 报 `TS6307`（文件不在项目文件列表里）。
   包名必须解析到 `dist`。
4. **改了 `src` 必须重新构建**依赖方才会看到新类型：`npm run build`，开发期用 `npm run watch`。

### 命令

| 命令                | 作用                                      |
| ------------------- | ----------------------------------------- |
| `npm run build`     | `tsc -b`，按序构建全部包                  |
| `npm run watch`     | 增量监听构建                              |
| `npm run typecheck` | 构建 + 检查测试与工具项目                 |
| `npm run verify`    | typecheck + 测试 + 格式检查（提交前必跑） |
